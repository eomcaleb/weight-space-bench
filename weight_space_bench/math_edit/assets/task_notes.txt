NOTES FROM THE EXPERIMENTERS (they apply from the start of the session):
1. Your forward-pass budget counts passes, not their size or how long they take: a generation pass with 256 answers per model ("both") or 512 answers costs the same one pass as a pass with 32. Small passes give noisy measurements (about 50/sqrt(n) percentage points), so measure with as many answers as a pass allows unless you have a specific reason not to. The time a pass takes does not count against you.
2. Separate generation passes do not reproduce each other exactly, even for the same request and weights (the server's batching changes the random numbers): compare edited and original only within one "model": "both" pass, and never repeat an identical request with unchanged edits (it costs a pass and adds little).
3. /work/eval_prompt_format.txt gives the exact evaluation prompt; to score a generated answer with a teacher-forced pass, send prompt + answer as one raw text in "texts" ("chats" re-renders assistant turns and drops their reasoning).
4. Before every pass, write to /work/notes.md the exact current edit (tensors, what was changed, strength) and the problem set, so that you can rebuild them if the conversation is restarted.
5. At the end, submit the best edit you found, the candidate with the best measured paired gain (on held-out problems if you measured it there), even if that gain is not statistically significant. Do not restore the original weights. In your final answer, report its measured gain with its standard error honestly; the experimenters evaluate it either way.
6. Failure counts in generation summaries: "cut_at_max_tokens" = stopped at max_tokens; "no_answer_finished" = finished, but the grader finds no final answer; "wrong_answer" = finished with a wrong final answer.
